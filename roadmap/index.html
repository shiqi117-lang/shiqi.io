LEARNING ROADMAP · 12 WEEKS

C++ 性能优化冲刺路线

12 周知识主线 + 4–6 周项目冲刺：不碰 CUDA，把权重压在面试高频和能产生数据的地方。

精通：能讲原理、能写代码、能答追问 熟悉：能讲清原理和权衡，不要求手写 了解：知道是什么、什么时候用

节奏

  • 知识主线 12 周（约 3 个月），走完阶段 01–08
  • 项目与冲刺 4–6 周（阶段 09），和主线分开算
  • 算法刷题全程并行，主线期间完成 150 题

主线只有 12 周，所以大量内容只要求「了解」。每个阶段都附了「仅了解 / 可跳过」清单，
那是这份计划能成立的前提——该跳就跳，别犹豫。

主线与项目期的分工

有些内容不适合塞进 12 周——要么耗时，要么做完就忘。它们统一放在项目期，
因为这些本来就是最好的项目素材：做出来能直接写进简历，比散在各阶段里强。

内容 归属 说明
矩阵乘法逐级优化（naive → 分块 → SIMD） 项目期 项目二的核心案例
1.5x vs 2x 扩容实测 项目期 结论先记住，实测留到项目期
手写简化 string 与 SSO 项目期 主线只要求知道 SSO 存在
完整 HTTP 服务器 项目期 主线只要求能解析请求行与 header
手写 hash map / 无锁队列 了解 读懂实现即可，全程不手写

怎么判断该不该跳过

拿不准时问自己三个问题：

  1. 过去半年我在面经里见过它三次以上吗？
  2. 面试官会不会追问到实现细节？如果会，我能现场写出来吗？
  3. 我能不能在两分钟内把它讲清楚，并说出一个使用场景？

三个都答不上来 → 标「了解」，写进 skip 清单，然后跳过。三个都能答 → 才值得投时间到「精通」。

明确放弃

页面底部有一份清单，包括 CUDA / GPU、分布式训练、HPC、游戏引擎、DPDK、编译器开发、RCU、eBPF。
它们不在这条路线的范围内。

01

现代 C++ 语言内核

进行中 精通 2 周

面试高频的语言特性全部能讲清原理、能写代码、能答追问。

学什么

  • 值类别与移动语义：lvalue / xvalue / prvalue、std::move 与 std::forward、完美转发、emplace_back vs push_back
  • 智能指针：unique_ptr / shared_ptr / weak_ptr、引用计数、循环引用、make_shared 为什么更好
  • RAII 与 Rule of 0/3/5、深拷贝与浅拷贝
  • 模板基础：函数与类模板、特化与偏特化、auto 与 decltype 推导规则
  • 四种类型转换与各自适用边界

做什么

  • 手写 unique_ptr 与 shared_ptr：含控制块、引用计数，并复现循环引用再用 weak_ptr 修掉
  • 手写简化 vector：Rule of 5、扩容策略、emplace_back
  • 整理 15 个表达式的值类别判定表
仅了解 / 可跳过
  • 协程：知道 co_await 是什么即可
  • Concepts / requires：能写一个简单约束就行
  • SFINAE 与模板元编程奇技：知道 void_t 和 enable_if 存在即可
  • 手写 optional / variant / function：改为了解 SBO 概念
  • 手写简化 string 与 SSO：知道 SSO 存在即可，实现留到项目时间
  • 1.5x vs 2x 扩容实测：知道结论（2x 浪费上限 50%，1.5x 有机会复用内存块）即可
关键产出手写 unique_ptr / shared_ptr / 简化 vector 资料Effective Modern C++ 条款 13–32（挑读）· cppreference

02

对象模型与内存布局

待开始 精通 2 周

能画出类对象的内存布局，说清多态的实现代价。

学什么

  • 类大小：内存对齐、padding、空类大小、成员顺序的影响
  • 虚函数表：vptr 位置、单继承与多继承布局、虚函数调用的开销构成
  • 为什么析构函数要 virtual；为什么构造函数不能是虚函数
  • new / delete 表达式 vs operator new vs malloc / free
  • 内存分区：栈 / 堆 / 全局 / 常量区；泄漏、越界、悬垂指针

做什么

  • 打印各类对象的 sizeof 与成员偏移，手画多继承对象布局图
  • 用 -fdump-lang-class 导出 vtable，验证你画的图
  • 实测虚函数调用 vs 普通调用的开销差（CRTP 静态多态作为对照）
仅了解 / 可跳过
  • Itanium ABI 完整规范：知道有这份文档、遇到问题会查即可
  • 虚继承的复杂布局：知道它解决菱形继承即可
  • IntrusivePtr 实现：了解思路即可，不手写
关键产出一份类布局分析笔记 + vtable 实测 资料深度探索 C++ 对象模型（挑读 1–4 章）· cppreference
03

标准库与数据结构

待开始 熟悉 1 周

能说清每个容器的实现与复杂度，并在面试里给出选型理由。

学什么

  • vector 扩容策略、reserve 的意义、迭代器失效规则
  • list / deque / map / unordered_map 的实现与适用场景
  • 迭代器失效全景：各容器插入删除后哪些迭代器还能用
  • 冷门但好用的接口：stable_sort、nth_element、lower_bound

做什么

  • 整理一张「操作 → 该用哪个容器」的速查表，写清理由
  • 用 perf-lab 实测一次 vector vs list 的遍历（数据留档）
仅了解 / 可跳过
  • 手写 hash map：改为读懂 Swiss table 的设计要点
  • allocator 完整实现与 std::pmr：知道概念即可
  • ranges / views
关键产出容器选型速查表 资料cppreference · abseil Swiss table 设计文档
04

编译链接与工具链

待开始 熟悉 0.5 周

能说清从源码到可执行文件的过程——这是后端面试高频题。

学什么

  • 预处理 / 编译 / 汇编 / 链接四步，每步产什么
  • 静态库与动态库的区别、链接期 vs 运行期
  • 符号、ODR、extern "C"、名称修饰
  • ASan / UBSan 怎么用、各自查什么

做什么

  • 手动走一遍 gcc -E / -S / -c / 链接，看每一步的产物
  • 给 perf-lab 的已有练习接上 ASan，确认零报告
仅了解 / 可跳过
  • -O0 到 -O3 各做了什么：知道有分级、优化会重排代码即可
  • LTO / PGO / BOLT：知道是什么、能解决什么问题即可
  • gdb 深度调试与 core dump 分析：会用 bt 看栈即可
  • CMake 系统学习：会写最简 CMakeLists 就行
  • C++20 modules
关键产出编译流程图解 + perf-lab 接上 ASan 资料CS:APP 第 7 章（链接）· cppreference
05

性能度量方法论

待开始 精通 1.5 周

这是你和普通候选人的分水岭——别人说「应该会快」，你拿数据。

学什么

  • 可复现基准：warm-up、多轮取中位数与 CV、控制变量
  • Google Benchmark：DoNotOptimize / ClobberMemory / PauseTiming 的坑
  • 火焰图怎么读；perf stat 看哪些指标
  • 微基准的三个经典陷阱：DCE、常量折叠、测到的是缓存不是算法

做什么

  • 在 perf-lab 里积累 2–3 个案例，每个都要有「现象 → 测量 → 根因 → 方案 → 收益」
  • 每个案例留优化前后的数字
仅了解 / 可跳过
  • perf record / 火焰图生成全流程：会用现成脚本即可（macOS 无 perf）
  • Roofline 与算术强度：知道概念、能一句话讲清即可
  • 自建性能回归 CI
  • 锁频 / 绑核实操：知道要这么做即可（macOS 不支持）
关键产出2–3 个完整的性能案例 资料Google Benchmark 文档 · perf wiki · perf-lab/bench/README.md
06

CPU 微架构

待开始 熟悉 1 周

能解释常见的 cache / 分支 / SIMD 现象，并给出改进方向。

学什么

  • 缓存层级、cache line 64B、伪共享及其代价
  • 分支预测与误判代价、likely / unlikely
  • 数据布局：AoS vs SoA、热冷字段分离
  • SIMD 与自动向量化：什么时候该用、怎么判断有没有生效

做什么

  • 伪共享实验：alignas(64) 前后对比
  • 分支预测实验：排序 vs 未排序数组
仅了解 / 可跳过
  • 矩阵乘法逐级优化：这是项目内容，留到项目时间做
  • 手写 SIMD intrinsics：会看自动向量化报告即可
  • 循环分块、展开、消除依赖链：知道思路，实操放项目
  • 流水线与乱序执行的微架构细节
关键产出两个可复现实验 资料Agner Fog 优化手册（挑读）· CS:APP 第 5–6 章
07

并发与内存模型

待开始 精通 2 周

面试高频区：线程同步、锁、原子、线程池都要能手撕。

学什么

  • 线程、互斥、条件变量；生产者消费者；死锁四条件与避免
  • 原子与六种 memory_order，重点 relaxed / acquire-release / seq_cst
  • 线程池原理与手撕
  • 伪共享、锁粒度、读写锁
  • 无锁编程的适用边界：知道什么时候不该用

做什么

  • 手写线程池：固定线程数 + 任务队列 + 优雅退出
  • 手撕生产者消费者：条件变量版与信号量版
  • 用 atomic 实现自旋锁，与 mutex 对比
仅了解 / 可跳过
  • 手写 MPMC 无锁队列：改为读懂一个实现
  • hazard pointer / RCU / epoch 内存回收
  • 协程调度器与有栈/无栈协程实现
关键产出线程池 + 生产者消费者 + 自旋锁 benchmark 资料C++ Concurrency in Action 2nd（挑读 1–8 章）· cppreference
08

系统编程与网络

待开始 熟悉 2 周

补上后端面试必考的 OS 与网络——原路线完全没有这块，不能空。

学什么

  • 进程 vs 线程、上下文切换、协程概念
  • 虚拟内存、页表、缺页中断、fork 写时复制
  • IO 多路复用：select / poll / epoll 的区别，LT 与 ET
  • TCP：三次握手 / 四次挥手、TIME_WAIT、滑动窗口、拥塞控制（概念层）
  • Reactor 模式与 one loop per thread

做什么

  • 写一个 epoll + Reactor 的 echo server，支持 LT / ET 切换
  • 压测并记录 QPS 与连接数上限，数据记进 perf-lab
仅了解 / 可跳过
  • io_uring：知道是新一代异步 IO 即可
  • DPDK、零拷贝深入
  • 拥塞控制算法细节（BBR / CUBIC 的公式）
  • 手写 HTTP 服务器完整实现：能解析请求行和 header 即可
关键产出一个能讲的 Reactor echo server 资料UNIX 网络编程（挑读）· man epoll · 小林 coding 网络篇
09

项目整合与面试冲刺

待开始 冲刺 额外 4–6 周

主线走完后，把产出打包成能讲 20 分钟的项目，并完成刷题与八股收尾。

学什么

  • 八股三科：C++ / OS / 网络高频题滚动复习
  • 项目讲述结构：背景 → 难点 → 你的方案 → 数据 → 复盘
  • 行为面试：实习经历用 STAR 表达

做什么

  • 项目一（必做）：高性能组件库 或 Reactor 网络库，二选一做深
  • 项目二（加分）：CPU 侧性能案例集——矩阵乘法逐级优化、伪共享、内存池、INT8 量化 matmul（纯 CPU / SIMD，不涉及 CUDA）
  • LeetCode 收尾到 150 题
  • 每周 2 次模拟面试，录音复盘
关键产出简历 + 两个能讲的项目 + 150 题 资料剑指 Offer · 代码随想录 · 你的错题本

三条原则

  • 高频优先 — 面试里出现过三次以上的知识点先吃透，冷门深水区直接标「了解」然后跳过。时间有限，不容许好奇心驱动。
  • 能讲清楚 > 完整实现 — Swiss table 你不需要手写，但要能说清它为什么比 std::unordered_map 快。
  • 结论必须有数据 — 每句性能优化的判断都要能在 perf-lab 里复现，这是你和普通候选人的分水岭。

并行轨道（全程不断，不占主线时间）

  • 算法刷题 — 150 题（数组 / 链表 / 二叉树 / 二分 / DP 基础 / 回溯），12 周内每周 12–13 题。优先刷高频题型，别在偏题上耗。笔试挂了后面全白搭。
  • 八股滚动复习 — C++ / OS / 网络三科，每周末 2 小时过一遍错题本。不要攒到最后。
  • 实习沉淀 — 把实习里碰到的每个问题按 STAR 记下来。「你做过什么」比「你学过什么」有分量得多。

明确放弃：不在这条路线范围内

  • CUDA 与 GPU 编程（含 cuBLAS / TensorRT / Triton kernel）
  • 分布式训练：NCCL、模型并行、数据并行、ZeRO
  • HPC / MPI / BLAS 调优
  • 游戏引擎：ECS、数据导向设计
  • 内核旁路：DPDK、RDMA
  • 编译器开发：LLVM pass、JIT
  • RCU / hazard pointer / epoch 内存回收
  • eBPF / Intel PT 深入分析
  • 手写 hash map 与 MPMC 无锁队列（改为读懂实现，不手写）

要避开的坑

  • 去啃 HPC 或编译器——对秋招零回报，不在这条路线范围内
  • 中途改主意去学 CUDA——会两头不扎实，CUDA 不在这条路线里
  • 只刷八股不写项目——面试三轮之后全是项目追问，没有产出会露馅
  • 刷题拖到最后——笔试挂了后面全白搭，主线期间每周必须完成配额
  • 性能优化只讲结论不给数据——「应该会快」在面试官那里等于没说
  • 把「了解」的内容当成「精通」准备——对照 skip 清单，别自我感动
