LEARNING ROADMAP

C++ 性能优化学习路线

以 C++ 为地基向性能工程深耕的九阶段路线：语言内核、对象模型、标准库、编译器、度量方法论、CPU 微架构、并发、系统层与领域深耕。

这份路线按 语言 → 内存 → 标准库 → 编译器 → 度量 → CPU → 并发 → 系统 → 领域 九级递进。顺序不是随意排的：前四级解决”写出正确且编译器友好的代码”，第五级解决”怎么判断快没快”，后四级才真正进入性能工程的主战场。

一个提醒：阶段 5（度量方法论）不要等到最后。从第一天就养成”优化前后必须留证据”的习惯，否则后面所有的优化结论都不可信。

01

现代 C++ 语言内核

进行中

从「会写」到「知道编译器看到了什么」。

学什么

  • 值类别：lvalue / xvalue / prvalue、引用折叠、std::move 与 std::forward 的实现
  • 对象生命周期与所有权：RAII、Rule of 0/3/5、异常安全三档保证
  • 模板：两阶段名字查找、ADL、SFINAE、变参模板、CRTP、type traits、if constexpr、Concepts
  • 编译期计算：constexpr / consteval / constinit
  • Lambda 到闭包类型的本质；C++20 协程的 promise_type

做什么

  • 从零实现 type_traits、optional、variant、tuple、function（SSO 版）、ScopeGuard
  • 用 Compiler Explorer 逐个看汇编，确认「零开销抽象」零在哪、不零在哪
  • 实现编译期字符串，体会模板元编程的编译时代价
关键产出手写 optional / variant / function 资料Effective Modern C++ · C++ Templates 第二版 · C++20 The Complete Guide
02

对象模型与内存布局

待开始

看到一个类，就能在脑中画出它的内存布局。

学什么

  • sizeof / alignof / alignas、padding 与字段重排、空基类优化（EBO）
  • 虚表结构、多重继承布局、虚继承、Itanium C++ ABI
  • new 表达式 vs operator new、placement new、std::launder
  • strict aliasing 规则与合法 type punning（memcpy / bit_cast）
  • 存储期：栈 / 堆 / .data / .bss / TLS

做什么

  • 用 -fdump-lang-class 导出 vtable 布局，手画多继承对象内存图并与 offsetof 对照
  • 写一个 arena / pool allocator，支持对齐与批量释放，与 malloc 做 benchmark
  • 用 pahole 分析真实项目结构体的 padding 浪费并动手重排
关键产出自研 arena allocator + benchmark 资料Itanium C++ ABI · pahole / clang -fdump-lang-class
03

标准库与数据结构

待开始

理解「复杂度相同 ≠ 性能相同」，常数因子才是主战场。

学什么

  • 容器内存布局：vector / deque / list 的 cache 行为差异与指针追逐代价
  • SSO、SBO 等小对象优化；内联缓冲的边界
  • 哈希：开链 vs 开放寻址，robin hood / Swiss table；flat_map / btree_map
  • Allocator 概念与 C++17 std::pmr（monotonic_buffer_resource）
  • Ranges / views 的开销与惰性求值陷阱

做什么

  • 实现 Swiss-table 风格 hash map，在插入 / 查找 / 遍历三个维度与 std::unordered_map 对比
  • 实现侵入式链表，对比 std::list 的遍历性能
  • 用 pmr + arena 改造一条热路径，量化分配次数下降
关键产出自研 flat hash map，压过 std::unordered_map 资料abseil::flat_hash_map · folly F14 · Boost.Container
04

编译器与构建

待开始

把编译器当合作者，而不是黑盒。

学什么

  • 编译链接模型：翻译单元、ODR、inline、模板实例化、符号可见性
  • 优化等级 -O0..-O3/-Os、-march=native、LTO、PGO、BOLT
  • UB 与编译器假设：有符号溢出、strict aliasing、未初始化读、noexcept、__restrict
  • 诊断：-Wall -Wextra -Wconversion、ASan / UBSan / TSan / MSan、clang-tidy
  • 编译速度与体积：PCH、C++20 modules、unity build、ccache、模板膨胀

做什么

  • 同一份代码在 gcc / clang × -O0/-O2/-O3 下对比汇编，找出内联与向量化的差异
  • 用 -fopt-info-vec 找出没被向量化的循环，改写后让它向量化
  • 给项目接上 CI：sanitizer + ASan/UBSan 回归
关键产出汇编对比报告 + sanitizer CI 资料Compiler Explorer · llvm-mca · bloaty · include-what-you-use
05

度量方法论

待开始

这一条决定你是「优化工程师」还是「玄学爱好者」。

学什么

  • 可复现基准：锁 CPU 频率 / 关 turbo / taskset 绑核 / warm-up / 多轮取中位数与方差
  • Google Benchmark：DoNotOptimize、ClobberMemory、参数化、libpfm 自定义 counter
  • 剖析：perf record/report、火焰图、off-CPU 分析、Top-Down（TMA）
  • 模型：Roofline、Amdahl 定律、Little’s Law、算术强度
  • 微基准陷阱：DCE、常量折叠、测到的其实是分支预测器或缓存

做什么

  • 建 perf-lab 仓库：benchmark 模板 + 一键锁频脚本 + 火焰图生成 + CI 回归
  • 立规矩：任何优化 PR 必须附前后对比数据，并写清 why
  • 练习说「这个优化不值得做」——可读性与正确性的账也要算
关键产出可复现的 benchmark 仓库 资料Google Benchmark · perf · Brendan Gregg 火焰图
06

CPU 微架构

待开始

把「cache 命中率」从口号变成可计算的量。

学什么

  • 流水线、乱序执行、超标量、分支预测与投机执行、分支误判代价
  • 缓存层级、cache line 64B、组相联、伪共享、硬件预取、TLB 与 huge page
  • SIMD：SSE / AVX / AVX-512 / NEON，自动向量化、intrinsics、std::simd
  • 数据布局：AoS vs SoA、结构体冷热拆分、位打包、指针压缩
  • 手法：循环分块、展开、分支消除（查表 / CMOV）、批量化、打破依赖链

做什么

  • 矩阵乘法逐级优化：naive → 循环交换 → 分块 → 展开 → SIMD → 多线程，每级记录 GFLOPS 并画在 roofline 图上
  • 矩阵转置、卷积、位计数、字符串查找各优化一遍
  • 分支预测实验：排序 vs 未排序数组，用 perf stat 看 branch-misses
  • 伪共享实验：两线程写相邻变量，加 alignas(64) 前后对比
关键产出矩阵乘法逐级优化 + roofline 分析 资料Agner Fog 优化手册 · Intel / AMD Optimization Manual · CS:APP 第 5-6 章
07

并发与内存模型

待开始

能判断「什么时候加锁就够，什么时候必须无锁」。

学什么

  • C++ 内存模型：data race 定义、happens-before、六种 memory_order、atomic_thread_fence
  • 锁的实现：futex、自旋 vs 阻塞、自适应锁、读写锁、锁粒度
  • 无锁结构：SPSC / MPMC ring buffer、CAS 循环、ABA 问题、hazard pointer、RCU
  • 伪共享与 cache line padding、NUMA 感知分配
  • 线程池、work-stealing、任务粒度与调度开销

做什么

  • 实现 SPSC → MPMC 无锁队列，与 mutex + deque 版本对比吞吐与 P99/P999 延迟
  • 用 TSan + Relacy / CDSChecker 验证正确性；用 perf c2c 找伪共享
  • 实现 work-stealing 线程池，跑并行分治负载看加速比
关键产出无锁队列 + TSan 验证 资料C++ Concurrency in Action 2nd · Is Parallel Programming Hard?
08

系统与内核交互

待开始

很多瓶颈不在你的代码里，而在你与内核的边界上。

学什么

  • 虚拟内存：页表、缺页中断、mmap / brk、page cache、huge page、内存映射文件
  • 系统调用开销与 vDSO；epoll / io_uring / sendfile / splice / 零拷贝
  • 上下文切换、调度器、cgroup、taskset、numactl、isolcpus
  • 高级剖析：perf 硬件事件、eBPF / bpftrace / uprobe、Intel PT、VTune
  • 存储：direct I/O、异步 I/O、写放大

做什么

  • echo server 逐级优化：阻塞 → 多线程 → epoll → io_uring → 零拷贝 → 绑核 / NUMA，每级记 QPS 与尾延迟
  • 用 bpftrace / perf 定位一次真实的上下文切换、缺页或 cache miss 热点
  • 对比 huge page 开启前后某内存密集程序的 TLB miss
关键产出高性能 echo server 优化报告 资料Linux perf · bpftrace · io_uring 文档
09

领域深耕与输出

待开始

性能优化必须落到一个领域，才构成竞争力。

学什么

  • 低延迟：尾延迟、busy-poll、无锁、内核旁路 DPDK
  • HPC / 数值：BLAS、稀疏矩阵、GPU offload、MPI
  • 存储 / 数据库：LSM、B+tree、列存、向量化执行
  • 游戏引擎：ECS、数据导向设计、SIMD、内存预算
  • 中间件 / 编译器：LLVM pass、JIT

做什么

  • 精读 1-2 个源码库：abseil、folly、EASTL、ClickHouse、RocksDB、Redis、LLVM
  • 提 PR，或独立写一个能讲清楚的小型系统
  • 持续写笔记，建立自己的性能案例库：现象 → 测量 → 根因 → 方案 → 收益 → 教训
关键产出开源贡献 / 个人性能案例库 资料abseil · folly · ClickHouse · RocksDB · LLVM

贯穿全程的三条原则

  • 先测量，再优化 — 没有基准数据的优化等于没做。优化前先建立可复现的 benchmark。
  • 数据结构优先于指令 — 大部分收益来自内存布局与数据组织，指令级技巧只是最后 20%。
  • 能解释才算会 — 每步优化都要能回答「为什么快了」，答不上来就是运气。

要避开的坑

  • 沉迷语言边角（UB 细节、模板奇技）而不落地写东西
  • 复制「十大优化技巧」却不测量，实际可能是负优化
  • 用微基准得出宏观结论
  • 忽略编译器已经做得很好的部分，手写反而更慢
  • 不控制变量：一边改代码一边换机器，数据全废
